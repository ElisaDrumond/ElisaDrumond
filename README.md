I build and evolve software across frontend, mobile and backend systems.

My experience comes from real products with business rules, integrations, payments, realtime communication, data processing and applications running in production.

I’m especially interested in what happens beyond the happy path: how systems evolve without starting over, how product constraints become maintainable code, how asynchronous work fails and recovers, and how technical decisions affect performance and reliability.

## Engineering focus

**Product engineering**  
Turning business rules, constraints and user workflows into explicit and maintainable software behavior.

**Frontend & mobile**  
Building web and mobile experiences with attention to state, rendering, performance and the boundaries between client and server.

**Backend & systems**  
Designing APIs, integrations and asynchronous workflows while thinking about data, failure modes and runtime behavior.

**Software evolution**  
Refactoring, testing and improving systems that already exist — without assuming a rewrite is the answer.

## How I think about software

- Make business rules explicit.
- Use the type system to prevent mistakes when it meaningfully can.
- Measure performance before claiming an optimization.
- Treat failures, retries and edge cases as part of the system.
- Add abstractions when the problem earns them.
- Understand an existing system before deciding to replace it.
